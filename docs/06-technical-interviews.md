# 06｜技术面试：按岗位练，不背一份万能题库

本章所有题目都是教学模拟，不是任何雇主的内部题、泄露题或保证会考的题。实际轮次、允许的工具、语言和评估方式，先向招聘方确认。练习目标是能解释、编码、调试和承认边界。

## 先问清面试形式

是否有在线编码、现场系统设计、ML 基础、论文讨论、项目深挖或 take-home？允许查文档或使用 AI 吗？题目是否有保密要求？每轮预计时长和提交方式是什么？录音、录屏必须遵守对方要求，不私自记录或公开。

一份准备计划应至少包含四种练习：不看答案手写代码、口头解释概念、画系统并讨论失败、打开自己的项目接受追问。

## 共通编码：六类题

| 练习 | 说明能力 | 最少边界测试 |
| --- | --- | --- |
| 统计日志中最高频的 k 个错误 | 哈希、排序、复杂度 | 空输入、k=0、并列频次、异常行 |
| 流式读取大文件并计算均值 | 迭代、数值与内存 | 空文件、坏值、极大值 |
| 合并带时间戳的预测与标签 | 数据粒度、键、延迟标签 | 重复键、迟到标签、缺失标签 |
| 批量调用服务并限制并发 | 并发、超时、资源控制 | 部分失败、超时、取消 |
| 计算多分类混淆矩阵 | 指标实现、标签空间 | 未知标签、零分母、长度不同 |
| 去重并划分训练/测试数据 | 数据泄漏意识 | 相同文本、同一用户、多次采样 |

先澄清输入、输出、规模和错误行为，给一个简单正确的方法，再讨论性能。不要在没有规模约束时主动设计复杂分布式系统。

### 一道可手算的指标题

教学数据：真实正类 10 个，模型预测正类 8 个，其中 6 个正确。则 TP=6、FP=2、FN=4；precision=6/8=0.75，recall=6/10=0.60，F1=2×0.75×0.60/(0.75+0.60)=2/3。没有总样本数，不能计算 accuracy。

追问：“把阈值提高会怎样？”合理回答是阈值会改变正类预测集合；通常 precision 和 recall 存在取舍，但具体变化要看分数分布，不能保证每次 precision 都严格上升。阈值应在开发集上选择，测试集只负责评估既定方案。

## 算法与机器学习：十二道主问题

### 1. 训练集、验证集、测试集分别做什么？

训练集学习参数，验证集选择模型/超参数/阈值，测试集评估冻结方案。追问预处理是否也需要分割后学习、反复查看测试结果是否等于调参。看过测试错误再改方案，应说明评测不再完全独立，建立新的留出集。

### 2. 你如何识别数据泄漏？

检查时间、对象和标签形成过程。例子是预测取消订单却使用取消后生成的退款字段；同一人的多次记录进入两个集合；在全部数据上拟合词表或缩放器。修复方式取决于泄漏机制，不是简单“随机重分一次”。[T01](../research/technical-sources.md)

### 3. 为什么不只报 accuracy？

看类别分布和错误成本。少数类很重要时，同时报告逐类 precision/recall、macro-F1、混淆矩阵与样本数。概率质量与阈值决策也应区分。指标选择取决于任务目标，不能宣布某个指标永远最好。[T02](../research/technical-sources.md)

### 4. 过拟合与欠拟合怎样区分？

比较训练和独立验证表现、学习曲线与错误类型。训练好、验证差是过拟合的一种信号，但也可能是分布变化或标签口径不一致。先查数据，再考虑正则化、模型复杂度、数据量和更合适的特征。

### 5. 梯度下降到底更新什么？

对于可微损失 L(w)，一次基本更新是 w←w−η∇L(w)。η 是学习率。能解释梯度的方向、维度和学习率过大/过小的表现。深度学习岗位再准备反向传播链式法则、mini-batch 与优化器差异，不能只背公式。

### 6. 逻辑回归为何能做分类？

先计算线性得分，再用 sigmoid 映射到 0–1 区间，用相应损失拟合参数，再用阈值做决策。输出值是否校准、阈值是否合理，需要数据验证。追问类别不平衡、正则化、特征缩放以及与线性回归的区别。

### 7. 朴素贝叶斯的“朴素”是什么？

在给定类别后，假设特征条件独立，用训练统计估计类别先验和特征条件概率。文本词汇并不真正独立，因此这是一个建模近似。平滑用于处理未见过的词/计数，log 概率可避免大量小概率相乘的数值问题。

### 8. 你怎样设计一次消融？

先写出假设，例如“二元词组能改善否定句分类”。固定数据、分割、主要参数和评测，只增加二元词组，报告总体与否定子集结果、计算成本和失败。若结果很小，不把它写成已经证实的普遍规律。

### 9. 离线提升为什么不一定在线有效？

可能存在数据分布、反馈机制、用户行为、延迟或选择偏差。解释评估对象与业务目标的差异，先做影子评估或受控小范围验证，并保留回退。若没有上线经验，可以用教学设计回答，但必须说清没有真实在线结果。

### 10. 论文里的新意与自己的贡献是什么？

用一张对比表说清相关方法、改变的部分、实验支持和失败。能指出何处是复现、何处是扩展、何处是共同工作。追问为什么选这个 baseline，以及能否被更简单的方法解释。

### 11. 分布变化怎么发现？

监控输入特征、输出分布和能够取得的真实标签，分层观察错误。输入变了不等于性能一定变差，性能变差也不一定只因输入变化。先验证采集和标签流程，再提出再训练、阈值或回退方案。

### 12. 深度学习研究岗还要补什么？

根据 JD 准备模型架构、损失、优化、训练循环、算力预算、内存、复现和相关研究。Transformer 方向能解释张量维度、注意力的作用与计算代价；大模型岗位能区分预训练、微调、偏好优化和推理评测。没有实际训练经历时明确承认，并用可复现实验说明已掌握的部分。

## AI 工程：八道系统问题

### 1. 给一个分类模型设计 API

澄清单条/批量、输入大小、模型版本、响应字段和延迟目标。先实现健康检查与预测，再增加校验和日志。异常应区分输入错误与服务错误。设计请求 ID 便于定位，但不要记录不必要的敏感原文。

### 2. 为什么只报平均延迟不够？

平均值可能掩盖慢请求。一起报告 p50/p95、错误率、并发、请求大小、预热方式、硬件和测量次数。样本量小的分位数波动很大。本仓库延迟报告仅反映本机一次测试，不能据此推断云端容量。

### 3. 模型更新怎样回滚？

模型和预处理配置一起版本化，验证输入/输出兼容性，保留旧版本，灰度观察质量和系统指标。出现问题回到已知版本，并保留故障输入。只回滚模型文件但保留新词表可能产生不兼容。

### 4. 训练与推理不一致怎么查？

核对特征顺序、缺失值、词表、标准化、版本与数据类型。建立一组固定输入，比较离线函数和在线 API 输出。序列化方案应避免加载来源不明的可执行对象；本项目使用可读 JSON 模型。

### 5. 超时是否应该无限重试？

不能。先判断操作是否幂等、错误是否暂时、请求是否有截止时间。限制重试次数并退避，避免放大故障。对可能重复扣费或执行外部动作的请求，要设计幂等键和确认机制。

### 6. 批处理一定更好吗？

它可能提升吞吐，也可能增加排队延迟和内存。需要按请求到达方式、模型计算、最大批大小和等待时间实验。不要把单线程循环称为经过优化的 GPU batching。

### 7. 什么时候需要分布式？

先量出当前瓶颈。数据、模型、吞吐或可靠性确实超过单机可行范围时，再讨论扩展方案及通信、协调、成本。训练基础设施岗需深入通信与硬件，普通应用岗未必要求同样深度。

### 8. 服务正常返回 200 就算成功吗？

不算。还需检查响应语义、模型质量、版本、时效与权限。HTTP 正常返回只是接口验收的一部分，还要验证响应语义与任务结果。监控应同时覆盖任务结果和系统状态。

## AI 应用工程：八道设计问题

### 1. 什么时候用检索，什么时候不需要？

知识有更新、来源要求或长文档查询时可以研究检索。固定规则和简单结构化查询可能直接用代码或 SQL。先比较简单方案，再选择模型与检索复杂度。

### 2. 检索与回答怎样分别评测？

先检查正确文档是否进入 top-k，再检查答案是否被文档支持、是否完整和是否应该拒答。检索命中不等于生成正确；引用存在不等于引用支持结论。用本项目的失败样本说明两者区别。

### 3. 文档中含有“忽略之前指令”怎么办？

把文档看作数据，不让它改变系统权限或工具规则。工具执行前做参数、目标和权限验证；有外部副作用时保留确认。基于关键词的拦截只能覆盖有限样例，不能被写成完整防注入方案。

### 4. 没找到可靠证据时怎么办？

按任务要求拒答、请求补充或转人工，明确缺失哪部分信息。拒答阈值在开发集选择，同时观察可回答覆盖率。全部拒答不是一个有用系统。

### 5. 缓存怎样避免串用户数据？

缓存键需要包含与答案有关的版本、检索范围和权限上下文。不能跨权限共享敏感回答。数据更新后还需失效策略。面试先说明隐私和正确性边界，再谈节省费用。

### 6. 结构化输出为什么还需要校验？

输出可能缺字段、类型错误或引用不存在。校验 schema、范围和业务约束，失败时受控重试或回退。JSON 能解析，不代表内容符合任务。

### 7. 如何比较两个 Prompt 或模型？

先固定任务集与评分规则，记录版本和调用条件，按可回答/不可回答、长短文本、语言等分层检查。生成具有随机性时重复运行，报告分布与成本，避免只展示最漂亮的一次。

### 8. 应用里哪些步骤不用 Agent？

确定的文件转换、字段校验、权限判断和简单计算优先由确定性代码实现。只有确有非结构化判断或动态任务需要时再引入模型。增加 Agent 数量不是技术成熟度指标。

## 项目深挖：一条追问链

“你为什么做这个项目？”→“最简单的方案是什么？”→“你如何证明改动有用？”→“测试集怎么来的？”→“哪条输入会失败？”→“改坏后怎么发现？”→“如果数据扩大十倍会怎样？”→“哪些部分是你自己写的？”

每一个答案都应能指向输入、代码、报告或真实经历。遇到未做过的部分，说“本项目没有验证这一点，我会这样设计实验”，比临时编一个生产故事更可靠。

## 行为面试：六个真实故事

准备一次失败、一次意见冲突、一次不清晰需求、一次时间取舍、一次主动发现问题、一次跨语言/跨文化协作。每个故事包含背景、责任、动作、结果、限制与反思。结果没有数字时用可核实的交付和反馈，不编造营收或录用。

**教学模拟结构：**团队想立即换更大模型，我先复现失败并发现标签口径不一致；我负责抽样与规则整理，同伴负责重标；结果以课程报告为准；没有上线，所以不能声称改善了真实用户体验。

跨文化题不要归因于国籍刻板印象。讲具体的沟通约定、文档、时区和验收差异，以及你如何减少误解。

## 一周面试训练

周一做一次基础诊断；周二手写两个编码题；周三演练 ML 或系统题；周四进行 30 分钟项目追问；周五录一次英文讲解；周六按对方规则完成限时模拟；周日只复盘证据最薄弱的一项。

评分分为“能否正确解释、能否独立实现、能否调试、能否说明限制、表达是否清楚”五项。不要用题目背诵数量代替准备质量。评分标准见面试自查模板。
